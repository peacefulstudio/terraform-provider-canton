# terraform-provider-canton v0.1.0

First stable release — a Terraform provider for administering parties, users, and rights on a [Canton](https://www.canton.network/) participant node via the Ledger API.

## What's new since v0.1.0-rc.1

### TLS connectivity through edge proxies

The provider now terminates TLS itself via a `grpc.WithContextDialer` that tolerates proxies (Envoy Gateway, Qovery) which don't echo `h2` back on ALPN. This is required to reach Canton participants fronted by most ingress setups since grpc-go 1.67 started enforcing ALPN. A non-h2 negotiation (e.g. a TLS-terminating HTTP/1.1 proxy) now fails loudly at the dialer instead of producing cryptic HTTP/2 framer errors on the first RPC.

### Configure-time health check

The provider issues a `VersionService.GetLedgerAPIVersion` ping with a 10 s timeout at configure time, so connectivity, TLS, and OAuth2 misconfigurations surface immediately rather than on the first CRUD operation.

### OAuth2 token refresh

Bearer tokens are now attached per RPC from a refreshing `oauth2.TokenSource`, so long-running `terraform apply` runs no longer 401 when a short-lived token expires mid-apply.

### Hardened URL parsing and plaintext warning

Scheme parsing is case-insensitive and trims whitespace. When `participant_url` is plaintext but an OAuth2 token is configured, the provider warns that the bearer token will be transmitted unencrypted.

## What's included

### Resources

| Resource | Description |
|----------|-------------|
| `canton_party` | Allocate a party on the participant (delete is a no-op — Canton parties are permanent) |
| `canton_user` | Create and delete a user |
| `canton_user_rights` | Grant and revoke user rights with in-place updates |

### Data Sources

| Data Source | Description |
|-------------|-------------|
| `canton_party` | Look up a party by ID |
| `canton_user` | Look up a user by ID |
| `canton_parties` | List all known parties on the participant |

### Authentication

- OAuth2 client credentials via the `oauth2` provider block
- Refreshing token source — short-lived tokens refresh automatically per RPC
- Environment variable fallbacks for all settings (`CANTON_PARTICIPANT_URL`, `CANTON_OAUTH2_*`)

### Other

- `terraform import` support for all three resources
- `participant_url` accepts full URLs (case-insensitive scheme, whitespace-tolerant)
- Configure-time health check fails fast on unreachable participants
- TLS 1.2+ enforced; plaintext + token emits a security warning

## Getting started

```hcl
provider "canton" {
  participant_url = "https://participant.example.com"

  oauth2 {
    token_url     = "https://auth.example.com/oauth/token"
    client_id     = var.canton_client_id
    client_secret = var.canton_client_secret
    audience      = "https://canton.example.com"
  }
}

resource "canton_party" "treasury" {
  party_id_hint = "treasury"
}

resource "canton_user" "service" {
  user_id       = "treasury-service"
  primary_party = canton_party.treasury.party_id
}

resource "canton_user_rights" "service" {
  user_id = canton_user.service.user_id
  act_as  = [canton_party.treasury.party_id]
}
```
