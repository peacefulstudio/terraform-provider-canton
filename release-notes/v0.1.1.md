# terraform-provider-canton v0.1.1

Patch release — first version installable from the [Terraform Registry](https://registry.terraform.io/providers/peacefulstudio/canton/latest). Functionally identical to v0.1.0; the change is in the release pipeline, not the provider itself.

## What's new since v0.1.0

### Terraform Registry compatibility

The release artifact set now includes a SHA256 checksum entry for `terraform-provider-canton_<version>_manifest.json`. The Registry validates that every file referenced by a release is checksummed before accepting the version, so v0.1.0 — which checksummed only the binary archives — could not be published. v0.1.1 closes that gap and is the first Registry-installable release; consumers can now drop the `dev_overrides` and source-builds and pin a real version.

This is a pipeline-only change. The provider binaries built for v0.1.1 are byte-for-byte equivalent to v0.1.0 in behaviour; if you've been pinning to v0.1.0 via a local mirror, switching to v0.1.1 from the Registry should be a no-op apart from the install path.

## What's included

### Resources

| Resource | Description |
|----------|-------------|
| `canton_party` | Allocate a party on the participant (delete is a no-op — Canton parties are permanent) |
| `canton_user` | Create and delete a user |
| `canton_user_rights` | Grant and revoke user rights with in-place updates |

### Data Sources

| Data Source | Description |
|-------------|-------------|
| `canton_party` | Look up a party by ID |
| `canton_user` | Look up a user by ID |
| `canton_parties` | List all known parties on the participant |

### Authentication

- OAuth2 client credentials via the `oauth2` provider block
- Refreshing token source — short-lived tokens refresh automatically per RPC, so long-running `terraform apply` runs no longer 401 mid-apply
- Environment variable fallbacks for all settings (`CANTON_PARTICIPANT_URL`, `CANTON_OAUTH2_*`)

### Other

- `terraform import` support for all three resources
- `participant_url` accepts full URLs (case-insensitive scheme, whitespace-tolerant)
- Configure-time health check (`VersionService.GetLedgerAPIVersion`, 10 s timeout) so connectivity / TLS / OAuth2 misconfigurations surface immediately rather than on the first CRUD operation
- TLS-terminating dialer that tolerates ingress proxies (Envoy Gateway, Qovery) which don't echo `h2` back on ALPN
- TLS 1.2+ enforced; plaintext `participant_url` with an OAuth2 token emits a security warning so bearer tokens aren't transmitted unencrypted by accident

## Getting started

```hcl
terraform {
  required_providers {
    canton = {
      source  = "peacefulstudio/canton"
      version = "~> 0.1.1"
    }
  }
}

provider "canton" {
  participant_url = "https://participant.example.com"

  oauth2 {
    token_url     = "https://auth.example.com/oauth/token"
    client_id     = var.canton_client_id
    client_secret = var.canton_client_secret
    audience      = "https://canton.example.com"
  }
}

resource "canton_party" "treasury" {
  party_id_hint = "treasury"
}

resource "canton_user" "service" {
  user_id       = "treasury-service"
  primary_party = canton_party.treasury.party_id
}

resource "canton_user_rights" "service" {
  user_id = canton_user.service.user_id
  act_as  = [canton_party.treasury.party_id]
}
```

## Verifying the release

The `SHA256SUMS` file is detached-signed with the Peaceful Studio Release Signing key (fingerprint `8687CAE1AD1207BBD51C4439E480E040DEB29BC2`, UID `Peaceful Studio Release Signing <releases@peaceful.studio>`). The Terraform Registry validates the signature against the public key registered for the `peacefulstudio` namespace; manual verification is also possible with the public key from the same fingerprint.
