# terraform-provider-canton v0.1.3

Patch release — `canton_party` import works against Canton 0.6.2, plus a documentation correction for `party_id_hint`.

## What's new since v0.1.2

### `canton_party` import accepts opaque party IDs

Canton 0.6.2 widened the shape of party IDs past the classical
`hint::fingerprint` pair: extra `::`-separated segments may appear, and the
upstream guidance is to treat IDs as opaque rather than parse their structure.
The v0.1.2 importer rejected any ID that didn't match the two-segment shape,
which made `terraform import canton_party.foo "<real-id>"` fail outright
against a 0.6.2 participant.

v0.1.3 rejects only empty IDs. The segment before the first `::` is still
surfaced as `party_id_hint` when present and non-empty — preserving the
classical convention for parties allocated with a hint — and IDs without a
usable prefix mirror the full ID into the hint instead. No schema changes;
existing state is unaffected.

### Documentation: `party_id_hint` is force-replacement

The v0.1.2 docs for `canton_party.party_id_hint` said *"changing it
post-allocation has no ledger effect"*, which read as if the field could be
edited freely. It can't — the schema marks it `RequiresReplace()`, so
changing the hint in HCL forces destroy/create and allocates a brand-new
party. The old party stays on the ledger (Canton parties are permanent) but
Terraform stops tracking it.

The reference page now spells this out and tells users to reconcile their
config to the imported hint after `terraform import`, never the other way
around. No behaviour change — the schema was always this way; only the
description was wrong.

### Source repository moved

This is the first release cut from
[peacefulstudio/terraform-provider-canton](https://github.com/peacefulstudio/terraform-provider-canton)
(public, Apache-2.0). Prior versions were built from a now-private
mirror. The published provider on the Terraform Registry
(`peacefulstudio/canton`) is unchanged; only the source repository visible
to contributors has moved. Releases continue to be signed with the same
Peaceful Studio Release Signing key (fingerprint
`8687CAE1AD1207BBD51C4439E480E040DEB29BC2`).

## What's included

### Resources

| Resource | Description |
|----------|-------------|
| `canton_party` | Allocate a party on the participant (delete is a no-op — Canton parties are permanent) |
| `canton_user` | Create and delete a user |
| `canton_user_rights` | Grant and revoke user rights with in-place updates |

### Data Sources

| Data Source | Description |
|-------------|-------------|
| `canton_party` | Look up a party by ID |
| `canton_user` | Look up a user by ID |
| `canton_parties` | List all known parties on the participant |

### Authentication

- OAuth2 client credentials via the `oauth2` provider block
- Refreshing token source — short-lived tokens refresh automatically per RPC, so long-running `terraform apply` runs no longer 401 mid-apply
- Environment variable fallbacks for all settings (`CANTON_PARTICIPANT_URL`, `CANTON_OAUTH2_*`)

### Other

- `terraform import` support for all three resources (now accepts opaque party IDs — see above)
- `participant_url` accepts full URLs (case-insensitive scheme, whitespace-tolerant)
- Configure-time health check (`VersionService.GetLedgerAPIVersion`, 10 s timeout) so connectivity / TLS / OAuth2 misconfigurations surface immediately rather than on the first CRUD operation
- TLS-terminating dialer that tolerates ingress proxies (Envoy Gateway, Qovery) which don't echo `h2` back on ALPN
- TLS 1.2+ enforced; plaintext `participant_url` with an OAuth2 token emits a security warning so bearer tokens aren't transmitted unencrypted by accident

## Getting started

```hcl
terraform {
  required_providers {
    canton = {
      source  = "peacefulstudio/canton"
      version = "~> 0.1.3"
    }
  }
}

provider "canton" {
  participant_url = "https://participant.example.com"

  oauth2 {
    token_url     = "https://auth.example.com/oauth/token"
    client_id     = var.canton_client_id
    client_secret = var.canton_client_secret
    audience      = "https://canton.example.com"
  }
}

resource "canton_party" "treasury" {
  party_id_hint = "treasury"
}

resource "canton_user" "service" {
  user_id       = "treasury-service"
  primary_party = canton_party.treasury.party_id
}

resource "canton_user_rights" "service" {
  user_id = canton_user.service.user_id
  act_as  = [canton_party.treasury.party_id]
}
```
